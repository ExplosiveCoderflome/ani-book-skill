# 同人写作

同人是独立路由。原作事实来自已授权的拆书工作区；新正文写在 `novels/<规范化同人名>/`，复用章节生产与连续性。不要把同人当成「换名仿写」，也不要把「续写」理解成接着别人的书往下贴原文。

读本文件前，确认来源已按 [book-analysis.md](book-analysis.md) 冻结，并且用户拥有或明确获准使用该来源。章节计划与正文仍按 [chapter-production.md](chapter-production.md) 与 [context-and-continuity.md](context-and-continuity.md) 执行。

## 两种模式

用户未指定时，先只问这一次，不默认续写，也不先写正文：

1. **接着已读断点往下写**：分支点是 `coverage-map.md` 里最后一章的章末，且该章笔记已经记到章末。笔记若停在章中，先补上章末再写交接。下一章承接的是章末尚未兑现的核心承诺推进，不是章内已经写过的那一拍。
2. **同人设、新故事**：沿用已读范围内的人名和透镜已记下的事实，从用户指定的章节之后另起一条线。

## 原作边界

只把已读分析当原作事实：`notes/`、`analysis-lens.md`、已同步的 `characters/`、覆盖地图里的已读范围。`remaining_scope` 与未写笔记的章节不是既定剧情。同人不得假装写成原作后文。

允许写入同人工作区的，是已读分析里已经记下的事实。记什么由该书的 `analysis-lens.md` 决定，不在本文件里预置题材栏目。通常包括：

- 原作姓名；
- 核心承诺、心理或关系推进，以及表层兑现轴各自停在何处；
- 透镜已写入角色卡的稳定特征与关系；
- 若透镜把规矩、身份或信息差标成闸门，则记下断点处的开关。

某本书的透镜没有写到的栏，交接里留空，不要为了填模板补上别的书才有的项目。

仍然禁止：

- 整段搬原文；
- 按原文句式仿写；
- 为了「贴后文」去读 `source/` 里尚未拆的章节；
- 把未读范围写成「原作就是这样」。

需要后文事实时，先回到拆书路线扩大已读范围，再更新同人的原作范围与交接包。

原创路线仍按 [book-analysis.md](book-analysis.md)：不把原作姓名、可辨认外貌组合和标志性桥段抄进原创 `novels/`。本文件只覆盖 `mode: fanfic` 的工作区。机制卡仍只服务换一本原创，不改成同人说明书。

## 工作区

```text
novels/<规范化同人名>/
├── novel-state.yaml
├── novel-brief.md
├── fanfic-handoff.md
├── characters/
├── continuity/
├── chapters/
└── ...
```

`novel-state.yaml` 最少记录：

```yaml
novel:
  title: "待定"
  mode: "fanfic"
  fanfic_mode: "continue_from_breakpoint"  # 或 new_story_with_canon
source_analysis:
  path: "analyses/<规范化书名>"
  fingerprint: "sha256:<value>"
  read_scope: "第X-Y章"
  branch_chapter: "第Y章"
```

`fanfic_mode` 只能是 `continue_from_breakpoint` 或 `new_story_with_canon`。

在已确认来源和分支后，可用 schema v3 控制器建立工作区；它会从拆书状态读取来源指纹，将 `fanfic_handoff` 设为唯一下一步，并跳过原创开书三项门槛：

```powershell
python scripts/novelctl.py init novels/<同人名> --title "<同人名>" --novel-mode fanfic --source-analysis analyses/<原作名> --fanfic-mode new_story_with_canon --read-scope "第1-3章" --branch-chapter "第3章"
```

交接完成后，按 `novelctl start-step`、`finish-step` 记录 `fanfic_handoff`，再推进简报和章节。控制器会阻止未就绪交接进入书级简报或章节生产，并将交接包纳入章节上下文。

## 开写前确认

跳过原创开书的「读者频道 / 发布形态 / 题材回报」第一轮。故事线和节奏不跳过。用户说「写一本」「写同人」，或只给一个前提，这两项仍算未明确，也不算授权 AI 决定。

先确认：

1. 原作分析工作区路径；
2. 续写断点，还是同人设新故事；
3. 分支章节（续写断点用覆盖地图最后已读章末；新故事由用户指定起跳章）。

然后只处理仍未决的项，每轮最多 3 个，每项 2–4 个互斥选项：

- **故事线**：新故事先定起跳章、第一段如何兑现核心阅读承诺、哪一步明确后移。只给了人物关系或一句前提时，先给出选项。未确认前不把交接标为 `ready`，不写正文。续写断点的下一步由章末笔记决定，不再另问「下一章写什么」。
- **节奏**：快、均衡或慢热，必须是用户确认或用户授权 AI 决定。慢热可以先建立选择及其压力，但仍须交付与核心承诺有关的阅读体验；不能把慢热等同于没有推进。

叙事视角、单章长度和内容边界仍按 [chapter-production.md](chapter-production.md) 的首章前门槛。不得把 AI 自选写成「用户确认」。

上述项未明确前，可以写同人简报草稿，`fanfic-handoff.md` 保持 `in_progress`。确认或授权后，才把交接标为 `ready`，再生成 `plan.md` 或 `draft.md`。

## 交接包

`fanfic-handoff.md` 是续写同人的硬上游。章节上下文包必须引用它。

交接栏位跟着已确认的透镜走：先保留核心阅读承诺、心理推进与关系结构，再记录表层兑现轴和主拆问题。表层事件不能替代核心承诺。某个维度不适用于本书时说明理由，不套用其他题材的观看、升级或关系模型。

```markdown
# 同人交接

- 分支点：
- 原作分析路径：
- 来源指纹：
- 已读范围：
- 同人模式：接着断点 / 同人设新故事
- 核心阅读承诺（core_reader_promise）：
- 心理推进与关系结构（不适用时说明）：
- 表层兑现轴（surface_progression）：

## 断点状态

按 `analysis-lens.md` 的主拆问题逐条作答。透镜没有的问题不新增栏目。

- 核心承诺已兑现到哪一步：
- 表层进展停在哪：
- 下一章必须兑现的变化及读者体验：
- 哪个角色选择、心理或关系后果能证明核心仍在：

## 知情差

只记会改变下一步选择的人。用角色名，不预设人称性别。没有信息差就写「断点无知情差」。

- 谁以为发生了什么：
- 实际上发生了什么：
- 谁在场 / 谁不知情：

## 闸门

仅当透镜把规矩、身份或信息差标成闸门时填写。否则写「本书透镜无独立闸门」。

- 此刻放行的：
- 此刻挡住的：

## 叙述口吻

- 视角与人称：
- 信息何时交给读者：
- 断点处已经出现、不能提前滥用的表达：

## 不可写

- 未读范围里的原作情节：
- 原文整段与原句仿写：
```

续写断点时，下一章的变化必须是章末尚未发生的推进，并说明它如何兑现核心承诺；心理、关系和信息位置的变化也可构成推进，不能强制改成外在升级。章内已有变化只记录在断点状态。闸门只留章末仍生效的开关。同人设新故事时，写清从哪一章的已读事实起跳，以及新线不继承哪些未读后文。

原作分析指纹或已读范围扩大后，将交接包标为 `stale`，按新笔记重算，再写下一章。

控制器在初始化及交接完成时记录 `source_snapshot`，在校验、上下文和生产入口复核来源的指纹、范围、覆盖类型及透镜状态。旧交接缺少快照或来源变化时，重做交接并核对已读范围；不能直接改 `ready` 绕过检查。

快照也锁定本次采用的分析文件内容与状态，包括透镜、总览、覆盖地图、分段笔记及已登记的 Markdown 产物。原文未变但作者纠正了拆书结论时，旧交接同样失效；更新交接后再推进，不能只核对原文指纹。

## 与章节生产的衔接

1. 读 `fanfic-handoff.md`、断点角色卡、上一同人章（若有）。
2. 按交接写章节合同：明确本章如何兑现核心承诺、推进何种心理或关系变化，以及表层事件的作用；保留保护事实，禁止未读外推。
3. 生成正文后，只把同人正文发生的事实写入同人连续性账本。不要回写拆书工作区，除非用户明确要求把同人当独立分析来源。

## 验收

- 模式已确认，分支点是已记到章末的最后一章。
- 交接包可执行。下一章要兑现的变化对得上该书透镜，并且在最后一章笔记里还没发生。章末已替换的旧闸门没有留在交接里。
- 正文未复述原文，未把未读章节写成原作事实。
- 审校用具体场景证据回答：若删去表层道具或升级，本章的核心体验是否仍成立？若只有外形相似，回到本章计划修正；不要仅凭模板字段齐全判定通过。
- `novel-state.yaml` 的 `mode` 为 `fanfic`，并指向有效的 `source_analysis`。
