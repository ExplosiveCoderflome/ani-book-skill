# 写法资产与表达合同

本页把原项目“写法引擎”的方法收敛为 Codex 可执行的文件合同：提炼写法、由作者选择、在一本书里固定生效，并用同一合同写作、审校和修文。写法只决定**怎样表达**，不得改写人物硬事实、世界规则、章节责任、读者回报或已确认的剧情。第一次开书不要求先配置写法；已有简报偏好足以开始，写出第一章后也可以再定。

需要补充外部方法时，按 [GitHub 写法与去 AI 化 Skill 来源](remote-skill-sources.md) 登记并审阅远端 Skill。远端内容只是候选方法来源，不是本书合同，也不会在章节生产时自动联网。

## 来源与保存

- 来源可以是作者自己的样文或已验收章节、明确的一句话读感，或有权使用的拆书笔记与机制卡。作者样文可提取叙述距离、句式节奏、对白差异和细节选择；第三方作品只提炼可迁移的非表达性方法，不复制专名、可辨识文风、标志性比喻、句式或原文段落。
- 需要跨书复用时，将作者确认的抽象规则保存在私有、默认 Git 忽略的 `styles/<名称>.md`。单书使用时直接建立 `novels/<书名>/writing-style.md` 即可；选用复用资产时，把选择后的规则写入这本书的 `writing-style.md`，记录来源路径和版本或指纹。它是**本书的有效快照**；源资产后来修改，不会静默改变已写章节或本书快照。
- 只保存少量有作用的规则。每条说明适用场景、预期读感、可观察的写法和不适用条件。样文、拆书原文与证据留在各自的私有来源，不装进章节上下文。
- AI 生成的写法候选先作为预览。用户确认、编辑，或明确委托 Codex 决定后才保存为本书有效合同；不把推荐伪装为作者选择。不确定时先用简报中的叙事偏好完成章节，再根据成稿提出可选建议。

`writing-style.md` 保持紧凑，便于每章完整回读；建议不超过 2200 字符。可按以下结构写：

```markdown
# 本书写法合同

- 状态：用户确认 / 用户授权 AI 决定
- 来源：作者样文 / 本书已验收章节 / 授权拆书结论 / 作者偏好
- 复用资产及版本或指纹：无 / styles/<名称>.md · <版本或指纹>
- 适用范围：全书；章节例外写在对应 plan.md

| ID | 正向写法与读者效果 | 适用条件 / 不采用什么 |
| --- | --- | --- |
| STYLE-01 | 让人物先行动、后交代动机，使开篇有即时压力 | 信息差需要保留时，不提前解释 |

| ID | 反模板化风险与可见证据 | 处理权限 |
| --- | --- | --- |
| AAI-01 | 连续几段由旁白解释人物感受，场景没有新动作或选择 | 允许定点修文 |
| AAI-02 | 特定叙述习惯可能变密；先由作者判断是否有意为之 | 仅提醒 |
```

## 本章有效写法

装配顺序为：书级 `novel-brief.md` 的读感和本书 `writing-style.md` → 当前 `plan.md` 明写的章节例外 → 用户对本次任务的明确要求。后两层只覆盖有冲突的**表达项**；未覆盖项继续生效。Codex 在章节计划与上下文包中记下有效规则 ID、来源和本章例外，不复制样文或整张写法资产。

写法与事实、人物动机、世界限制、内容边界、章节义务或读者承诺冲突时，先守住这些硬约束，再改写或暂缓表达规则，并说明原因。来自拆书的技法是写作方法，不是本书事实；原创书不能借此带入来源作品的专名、关系或情节。

没有本书写法文件时，直接使用简报已确认的视角与节奏，以及 [中文小说反模板化二稿](chinese-novel-humanization.md) 的少量通用基线；不得因为缺少写法资产而阻塞开书或章节生产。

## 同一合同贯穿章节

1. **初稿**：用有效正向写法与少量反模板化约束组织视角、对白、场景和节奏，不靠禁词表或固定句长比例生成。
2. **二稿**：按 [中文小说反模板化二稿](chinese-novel-humanization.md) 检查成簇、影响阅读的问题。没有实质问题的段落保留原样；不得为了“去 AI”机械重写整章。
3. **审校**：在同一份 `review.md` 里记录规则 ID、正文位置、具体证据、对读感的影响和处理建议。单个正常标点、一次常用句式或外部检测分数不构成硬问题。
4. **修文与复验**：只对已定位且允许修文的表达问题作最小修改，再用相同写法合同及章节事实合同复验。标为“仅提醒”的规则只入质量提醒，由作者决定；普通表达问题不单独触发整章重写或全书重规划。

用户改变写法时，保护已有正文；重建后续未稳定章节的上下文与审校目标。作者对初稿和二稿的选择可形成**待确认**的新规则建议，不能自动改写长期写法资产。外部检测器只提供观察值，不证明作者来源，也不驱动为了分数的修文。

保存或修改有效的 `writing-style.md` 后运行 `novelctl.py reconcile <workspace>`：登记可选写法工件及指纹，将其接入后续上下文与审校依赖；变更使未稳定的依赖产物失效，已提交章节及受保护正文保持原样。首次没有此文件时无需创建空合同。

## 接收作者纠正

纠正发生时，先区分它针对用词、表达方式还是故事设定，并将原意与适用范围写回现有权威文件：表达要求进本书写法，故事要求进简报，单章例外进计划。用户已明确的纠正直接生效，不为落盘重复请求确认；只有影响高且无法推断的范围才询问。

不能把对某种设定或叙事方式的否定处理成近义换词。改后回读相关设定、人物动机与计划，检查同一问题是否换了名称继续存在；仅明确禁止某个词时，也不要擅自禁止整个题材。下一次恢复先回读这些有效要求，不依赖旧聊天记忆。一次作品偏好不升级为所有小说的永久禁令。
