## 目标与边界

拆书的目标是把已授权来源转成可核对、可继续加工的创作知识，而不是复述原作、替代阅读或生成贴近原作的仿写稿。默认产物是分段笔记、八类分析小节、证据账本、覆盖地图和机制卡。

只分析以下来源：

- 用户提供、拥有或明确获准使用的 TXT、Markdown、正文片段或小说工作区；
- 无需绕过登录、付费墙、验证码、反爬限制即可访问的公开网页；
- 用户自己的稿件，此时使用诊断模式。

不要绕过访问控制，不要批量复制受保护正文，不要在公开仓库保存原文或包含大量原句的分析工作区。网页不可访问时，说明缺口并请用户提供文件。引用只保留支撑判断所需的短证据，并记录章节或页面来源。

用户授权且可访问的来源一律按本文件执行。不要按题材、套路或道德观拒绝、跳过步骤或改写原文事实。笔记以读者实际拿到的回报为重心。规矩、代价和信息差只在它们放行或挡住这个回报时记录。角色年龄、身份和关系以原文陈述为准。

## 选择目标、范围与深度

先确定一个主要目标：

- **结构学习**：故事发动机、阶段推进、冲突升级、高潮与回报。
- **人物学习**：角色功能、关系网络、成长弧、关键选择和形象变化。
- **写法学习**：视角、场景组织、对白、信息释放、节奏和断章。
- **商业学习**：点击驱动、读者承诺、爽点循环、付费拉力和流失风险。
- **稿件诊断**：检查用户作品的结构、人物、节奏、连续性和卖点。
- **综合拆书**：在预算允许时覆盖全部维度。

选择一种深度：

| 深度 | 默认范围 | 默认产物 |
| --- | --- | --- |
| 快速 | 用户指定范围，或有代表性的开篇与关键节点 | 覆盖声明、总览、主要优劣势、3-5 张机制卡 |
| 标准 | 可获得的完整范围，分段处理 | 总览、八类小节、证据账本、机制卡 |
| 深入 | 完整范围或明确的高质量抽样 | 标准产物，加阶段变化、反例检查、读者体验曲线和角色专题 |
| 诊断 | 用户自己的稿件范围 | 问题分级、证据、影响、最小修复和重检点 |

范围使用章节边界表达；没有可靠章节标题时使用稳定片段编号和字符区间。只有实际处理了全部范围，才可标记 `coverage: full`。其他情况一律标记 `coverage: sampled`，并列出未覆盖范围。

## 创建分析工作区

需要跨任务继续或分析长文本时，使用：

```text
analyses/<规范化名称>/
├── analysis-state.yaml
├── analysis-lens.md
├── source-manifest.md
├── source/
│   └── <original-filename>
├── coverage-map.md
├── notes/
│   └── segment-001.md
├── sections/
│   ├── overview.md
│   ├── plot-structure.md
│   ├── timeline.md
│   ├── character-system.md
│   ├── worldbuilding.md
│   ├── themes.md
│   ├── style-technique.md
│   └── market-highlights.md
├── evidence-ledger.md
├── uncertainty-ledger.md
├── pattern-cards.md
├── characters/
│   └── CHAR-001.md
├── graph/
│   ├── nodes.jsonl
│   └── edges.jsonl
├── retrieval/
│   └── analysis-index.sqlite3
└── recovery.md
```

冻结来源时，将用户提供的本地原文文件或章节目录复制到工作区 `source/`，保留原文件名，作为只读快照。网页来源在可保存的前提下同样放入 `source/`。检索索引不读取 `source/`。`analyses/` 默认不进入公开仓库，因此快照不得提交到公开 git。引用仍只保留短证据。

`source-manifest.md` 同时记录用户原路径与工作区内快照路径、类型、标题、作者或站点、访问日期、来源版本、指纹、授权说明和实际分析范围。续拆时优先读 `source/` 快照；快照缺失或指纹不一致时，再回到用户原路径并重新复制。

保持 `analysis-state.yaml` 简短：

```yaml
schema_version: 1
analysis:
  title: "待定"
  profile: "standard"
  status: "in_progress"
core_model:
  status: "missing"
  reader_promise: null
  subject_matter_or_fantasy: null
  psychological_progression: null
  relationship_structure: null
  gates_and_costs: []
source:
  kind: "local_file"
  ref: "<path-or-url>"
  fingerprint: "sha256:<value>"
  coverage: "sampled"
  scope: "第1-11章"
  remaining_scope: "第12-194章"
artifacts:
  overview:
    path: "sections/overview.md"
    status: "missing"
character_sync:
  status: "unconfirmed"
  targets: []
analysis_lens:
  path: "analysis-lens.md"
  status: "missing"
next_action:
  type: "confirm_coverage_mode"
  target: "source"
```

使用 `missing`、`in_progress`、`ready`、`stale`、`blocked`。用户编辑过的分析产物默认受保护。来源指纹、版本或范围改变时，将依赖它的 notes、分析小节和机制卡标为 `stale`，不要静默重写。

## 运行分层拆解

### 1. 冻结来源

记录来源、权限、版本、指纹、范围和分析目标。网页来源记录具体章节 URL；同一 URL 内容变化时视为新版本。无法确认完整目录时，不声称覆盖整书。将本地原文复制到 `source/` 后再写清单。

写出任何笔记之前，对本地原文文件或章节目录运行：

```powershell
python scripts/estimate_analysis_tokens.py <原文文件或目录>
```

把内容字符、计划切段数和原文 token 区间告诉用户。这是按长度估算的区间，不是模型账单。笔记阶段大约把原文读入模型 1 遍；后续总览和专项读笔记，不要把该区间再乘小节数。还没有本地全文时，先请用户提供文件再估算。

脚本输出 `confirm_required: true`，或用户尚未选定范围时，立刻停止，不要写笔记。只给出两项：

1. **全文拆解**：覆盖当前可获得的全部范围；`coverage: full` 仅在确实读完该范围后使用。
2. **部分拆解**：先处理一个有边界的窗口。用户指定章节或字数区间时用该窗口；未指定时用下面的抽样节点，并写出未覆盖范围。

部分拆解不是一次性截断。`coverage-map.md` 必须留下可继续的 `remaining_scope`；用户说继续拆时，只新增下一段 notes，不重写已完成笔记。

在用户确认前，将 `next_action` 设为 `confirm_coverage_mode`。

### 1.1 生成本书临时拆解透镜

为当前这本书写一份只在本工作区生效的临时拆解技能。不同书的重心不同。不要用同一套八类小节平均用力，不要从预设题材菜单里选，也不要套用其他书的透镜。

透镜必须把**核心阅读承诺**和**兑现方式**分开。核心阅读承诺是读者反复追逐的题材幻想、情绪体验或问题；兑现方式是每段可指认的行为、能力、线索、关系或场面变化。身体、升级、揭示和场面都是载体，不能单独替核心观念下结论。闸门是规矩、身份、信息差、愧疚、主题词和世界限制，它们可能只是放行条件，也可能正是核心阅读承诺的一部分；先用证据判断，不预先降权。

范围确认之后、第一批笔记之前按下面的顺序生成。已有笔记但还没有透镜时，在下一批笔记前补做，不回改已完成笔记。

1. **取样。** 读已确认窗口的开篇，再读窗口中后部一段。已有笔记时读笔记，不重读全文。
2. **列出 2–3 个核心候选。** 每个候选都写清题材母题或核心幻想、读者心理回报、至少两个独立证据簇和一个反例或限制。不要只因出现一个关键词就定性，也不要把用户的局部拆解问题伪装成整部作品结论。
3. **确认核心阅读承诺。** 写 `core_reader_promise` 一句，并另写 `subject_matter_or_fantasy`、`psychological_progression`、`relationship_structure` 和 `gates_and_costs`。若作品依赖三方或多方关系，明确记录参与者、刺激对象和叙述者的观看/知情位置。
4. **再写兑现轴。** 用 `surface_progression` 描述读者能在段落中核对的变化，例如身体或亲密行为、能力或资源、关系选择、真相或生存压力。兑现轴至少列两条，不能让它单独替代核心阅读承诺。
5. **做反事实检查。** 按题材移除被怀疑承载核心的要素，例如关系中的选择、解谜中的真相代价、成长中的能力变化，判断读者回报是否明显坍塌。关系作品可进一步检查第三者、观看位置或比较对象。若坍塌，必须把该关系或位置写进核心结构；若不坍塌，才可把它作为普通闸门或场面手段。
6. **写 3–5 个主拆问题。** 至少一个问题问核心阅读承诺如何被加强或威胁，至少两个问题问兑现轴怎样变化，必要时再问闸门如何放行或阻挡。关系型题材必须回答：谁想要什么、谁被观看或比较、谁控制信息、谁承担失去或曝光的代价。答不出时写「本段未移动」。
7. **写降权、笔记形态、角色卡侧重和修订条件。** 角色卡记录角色功能与核心欲望，再按文本实际机制选记刺激对象、观看位置、关系代价或可撤回边界；原文未支持的动机留为推断或假设。笔记先保留可核对事实，再绑定到核心候选和兑现轴。场面不整段抄入。
8. **自检，不过就重写，不要把失败稿交给用户。** 透镜必须能解释标题/开篇承诺、至少两个阶段的重复回报和一个反例。若把专名盖住后只剩“身体推进”“关系变化”或“信息差”，说明核心仍然太泛。若核心候选之间未完成比较，不能标为 `ready`。
9. **确认后再写笔记。** 自检通过后，向用户展示核心候选、推荐的 `core_reader_promise`、兑现轴和主要问题。`analysis_lens.status` 设为 `pending_confirm`，`next_action` 设为 `confirm_analysis_lens`。用户点头前不写下一批笔记。用户纠正后按纠正重写，再确认一次。确认后标 `ready`。`character_sync` 仍是 `unconfirmed` 时，可与这次确认放在同一轮。
10. **持续纠偏。** 后续证据若改变题材核心、刺激对象、关系结构或心理推进，即使表层兑现轴没有改变，也必须把透镜重新设为 `pending_confirm`，并将依赖它的总览、机制卡和角色专题标为 `stale`。不要等到“主产品变了”才纠偏。

`analysis_lens.status` 只用 `missing`、`pending_confirm`、`ready`。续拆时先读已确认的透镜，再写笔记；恢复时同时回读 `core_reader_promise` 和 `surface_progression`，不能只读表层兑现轴。

### 2. 切分原文

优先识别标准中文章节标题、序章、番外和卷标题。章节边界不可靠时按约 6,000-16,000 字符切分，目标约 10,000 字符，并保留少量边界重叠以避免事件被截断。长书分批处理，不把全部原文一次塞入上下文。

每个 segment 使用稳定 ID，并记录：章节范围、字符范围、来源指纹、前后衔接和是否完整。

「是否完整」指笔记有没有记到所标章节的章末，不是指场面本身有没有结束。章末若还有主产品上的变化，或换掉了本章前面的闸门，必须记入。只记到章中，就写明停在哪一拍；覆盖地图不得把这一章标成已读章末。同一章里后出现的闸门替换先出现的闸门，断点只保留章末仍生效的那个。

长篇来源完成首批 notes 后，按 [book-analysis-retrieval.md](book-analysis-retrieval.md) 建立轻量检索索引。关系追踪优先走 BookGraph，明确名称和事实优先使用元数据与全文检索，向量只做可选语义补召回。

### 3. 生成低推断笔记

每个 segment 只提取当前范围能支持的内容：

- 片段摘要与剧情节点；
- 时间事件和状态变化；
- 人物、关系、目标、行动与结果；
- 世界规则、势力、资源与限制；
- 主题、情绪和意象信号；
- 叙事技法、语言和场景组织信号；
- 读者满足点、钩子、回报和潜在流失点；
- 最多几条短证据及来源锚点。

不要在这一层断言整书主题、作者意图、隐藏动机或确定的商业结论。材料不足时留空，不要凑项。

`analysis-lens.md` 为 `ready` 时，以透镜的核心阅读承诺、兑现轴、主拆问题和降权项增减上面的默认条目。透镜未写到的栏仍可留空。

### 4. 先生成总览

首批笔记已经覆盖一个可解释的行动闭环时，就可生成明确限定范围的局部总览与少量机制候选，供作者尽早用于原创规划；不必等整书拆完。每条候选仍需回读证据、说明前提和反例，材料不足时继续笔记而不凑卡。新笔记出现后增量更新相关结论，保持 `source.read_scope` 与覆盖地图一致。

总览先固定一句话定位、题材、核心阅读承诺、目标读者、整体优势、整体短板和覆盖限制。后续小节使用它作为口径锚点，但仍必须由各自相关 notes 支撑。

### 5. 生成专项小节

| 小节 | 必须回答的问题 |
| --- | --- |
| 剧情结构 | 主线如何启动和重复运转；阶段如何升级；高潮、损失与回报怎样分布 |
| 时间线 | 关键事件顺序、阶段划分、角色状态变化和时间跨度风险 |
| 人物系统 | 主角发动机、配角与反派功能、关系网络、弧线和功能重叠 |
| 世界观 | 规则、资源、势力、舞台、限制，以及设定怎样实际推动剧情 |
| 主题表达 | 核心主题、情绪基调、母题及其通过行动而非口号出现的方式 |
| 文风与技法 | 视角、语言、描写、对白、节奏、信息释放、开章和断章方法 |
| 商业卖点 | 点击驱动、持续追读理由、爽点循环、读者匹配和商业风险 |
| 总览 | 上述结论的低风险汇总、覆盖声明和最值得继续深挖的问题 |

每个小节同时保存可读 Markdown 和紧凑的结构化结论。不要把大段分析重复复制到结构化层。

### 单人角色拆解

`sections/character-system.md` 只保留全员功能图。单人拆解放在 `characters/<CHAR-ID>.md`，一人一份。

`analysis-state.yaml` 的 `character_sync.status` 只能是 `unconfirmed`、`on`、`off`。用户未选择时保持 `unconfirmed`，不要默认只写主角，也不要给每个有名字的人建档。

范围确认时若该项仍是 `unconfirmed`，与覆盖模式一并询问；若当时未问，在第一批 notes 写完、写角色卡之前必须停问。只给两项：

1. **不同步**：角色只留在 notes 和人物系统的一行功能里。
2. **同步拆角色**：用户点谁写谁；未点名时只跟踪主角，以及本段会改变其选择的对手。点名多人时仍一人一份，不按路人建档。

选「不同步」后，除非用户改口，不再生成 `characters/*.md`。

选「同步拆角色」后：

- 第一批 notes 一完成就建卡，不等总览。
- 原文一旦出现体型、面容、发型、胸臀腰腿、体态、声音或稳定着装，优先写入「形象与身体」，再写发动机。没写到的栏留空，不补全、不美化。
- 之后每完成一批 notes，只追加已读阶段：弧线加一行，关系只改「阶段变化」，形象与身体只补新出现的稳定特征；着装、伤病、气质变化写入「呈现变化」。不重写早段事实行，除非原文证据证明记错。
- 材料不够的栏留空。开篇形象不能写成全书弧线。未读范围标在覆盖里。
- 覆盖扩大后，总览和专项标 `stale`；角色卡不标整份 stale，只续写新阶段。


用户要把这张卡用于**原创**小说时，只迁移功能、手段、阻力、回报和可抽象的辨识方式，写入故事发动机或角色职责。不把原作姓名、可辨认外貌组合和桥段抄进原创 `novels/` 的角色档案。

用户要写**同人**时，按 [fanfic.md](fanfic.md) 处理：可沿用已读范围内的姓名，以及该书透镜已经记下的事实；不可复述原文，不可把未读章节写成原作事实，也不可把另一本书的栏目套进交接。同人正文写在 `mode: fanfic` 的小说工作区，不回写拆书笔记。

### 6. 做跨尺度综合

分别观察三个尺度：

- **章级**：目标、冲突、转折、回报、净变化和结尾拉力；
- **阶段/卷级**：目标切换、地图变化、对手升级、关系重组和阶段兑现；
- **全书级**：故事发动机、成长循环、揭示梯度、高潮序列和结局回收。

比较不同阶段的指标和模式，标出真正的变化点。不要把开篇特征直接外推为全书规律。

### 7. 生成机制卡

每张机制卡只沉淀可迁移原理：

```text
PATTERN-001｜机制名称
来源范围：第 X-Y 章
核心阅读承诺：
刺激对象：
观看位置：
心理推进：
回归/依恋：
解决的问题：
运行机制：
必要前提：
读者回报：
失败方式：
反例或边界：
安全改造方向：
不可照搬元素：专名、独特设定、标志性桥段、原句表达
```

机制卡必须解释“为什么有效”和“换一个故事怎样重新设计”，不能只把原作桥段换名复刻。若用户要把机制用于**原创**新书，将它映射到 `novel-brief.md`、故事发动机、卷职责或章节合同；按 [analysis-to-novel.md](analysis-to-novel.md) 整理可校验的 `pattern-cards.yaml`、证据指纹和章节参考清单，再接入上下文与审校。只有笔记时先整理机制，不直接生成仿写正文。机制卡不是同人节拍表；同人写作走 [fanfic.md](fanfic.md)。

## 证据与不确定性合同

关键结论使用稳定 ID，例如 `CLAIM-001`，并记录：

- `kind`：`fact`、`inference` 或 `hypothesis`；
- `confidence`：`high`、`medium` 或 `low`；
- `scope`：适用章节或阶段；
- `source_refs`：章节、segment、URL 或字符区间；
- `evidence`：必要的短摘录或事实摘要；
- `counterevidence`：不符合该模式的章节或现象；
- `status`：`supported`、`contested`、`open` 或 `stale`。

事实只描述原文明确发生的内容。推断必须说明依据和适用范围。假设进入 `uncertainty-ledger.md`，不能伪装成事实。强结论优先要求两个独立来源锚点；只有一个锚点时缩小范围或降低置信度。

## 范围确认与增量续拆

高消耗时不得默认全文，也不得静默改成抽样。用户确认后写入：

| 字段 | 含义 |
| --- | --- |
| `coverage` | `full` 仅当已处理全部可获得范围；其余为 `sampled` |
| `scope` | 当前已确认并正在处理或已完成的窗口 |
| `remaining_scope` | 尚未处理、可增量续拆的窗口；没有剩余时写 `none` |

`coverage-map.md` 最少四栏：已读、本轮抽样、未覆盖、不可访问。未覆盖范围使用稳定章节号或字符区间，便于下一轮直接取用。

增量续拆规则：

1. 先读 `analysis-state.yaml`、`analysis-lens.md` 与 `coverage-map.md`。透镜缺失或仍是 `pending_confirm` 时，先比较并确认核心阅读承诺、心理/关系推进与表层兑现轴，再只取 `remaining_scope` 中的下一段，或用户新指定的窗口。
2. 新 notes 使用下一个空闲 `segment-NNN`，不改写已有笔记。
3. 来源指纹未变时，不把旧 notes 标为 `stale`。覆盖扩大后，将总览、专项小节、机制卡和角色卡标为 `stale`，按新 notes 重算，不要把开篇规律外推到新窗口。
4. 新 notes 写入后重建检索索引。
5. 更新 `scope`、`remaining_scope` 和唯一 `next_action`。用户未要求下一窗时，停止并报告剩余范围。

## 大体量作品的覆盖策略

部分拆解且用户未指定窗口时，按节点抽样，不要随机截取：

1. 开篇承诺与首个行动闭环；
2. 每卷开端、中点、高潮和卷末；
3. 主要人物首次进入、关系转折和退出节点；
4. 规则首次建立、首次被利用和首次付出代价的节点；
5. 全书关键揭示、低谷、终局和尾声；
6. 用户特别关注的范围。

结论必须标明只适用于已读窗口。未覆盖范围留在 `remaining_scope`，供后续增量续拆。

## 新增的质量检查

在交付前检查：

1. **覆盖诚实度**：报告是否明确区分全量与抽样。
2. **证据覆盖率**：关键结论是否有可定位依据。
3. **反例压力测试**：强规律是否检查过不符合它的章节。
4. **阶段漂移**：人物、节奏、文风或卖点是否在中后期发生变化。
5. **因果完整性**：是否说明机制的前提、行动、阻力、结果和回报，而不只是列标签。
6. **跨节一致性**：总览与人物、结构、市场小节是否冲突。
7. **可行动性**：机制卡是否能指导原创设计，同时保持足够改造距离。
8. **复述风险**：是否包含不必要的大段原文、过密情节复述或贴近原作的仿写指令。
9. **透镜对齐**：笔记是否同时回答已确认透镜的核心承诺和兑现轴问题。若多数只在问闸门或只在记表层变化，透镜本身不合格，先重写再继续笔记。
10. **章末记全**：标成已读的章节，笔记是否记到章末。章中截断不能当成下一章的起点。

## 诊断用户稿件

诊断模式沿用同一分段与证据链，但将每个问题写成：问题、证据、影响范围、严重度、最小修复、需要重检的下游产物。优先记录非阻塞质量债，再做局部修复；只有故事责任本身无法成立时才建议重规划。

未经授权不要修改原稿。用户批准修复后，先保护稳定正文和已成立内容，再按 [quality-and-repair.md](quality-and-repair.md) 执行。

## 恢复与交付

每完成一个 segment 或小节就保存结果并更新 `analysis-state.yaml`。单个小节失败时保留其他成功产物；恢复时只处理 `missing`、`stale` 或明确要求重做的部分。

最终报告必须包含：来源与授权边界、实际范围、覆盖类型、完成小节、关键结论、证据与不确定性、机制卡、未覆盖缺口和一个推荐下一步。
