# 更新记录

本文件记录面向使用者的主要变化。开发中的内部调整不一定会单独记录。

### 2026-10-15

- 优化：重新设计首页品牌横幅，采用米白底、黑色排版与钴蓝书页线条，同步中英文图片说明。
- 优化：中英文首页新增从第一个想法到小说完本、从来源文本到拆书交付的完整路线图，说明逐章循环、全书收束、稳定导出、分批阅读、覆盖缺口及创作接入，并提供可直接使用的开始与恢复指令。
- 优化：完善中英文首页，集中说明拆书到原创/同人的三种路线、写法与去 AI 化、定稿版本保护、跨书复用及本地阅读台，并补齐可执行的安装与工作区操作指引。
- 新增：可核验 GitHub 写法与去 AI 化 Skill 候选的本地文件、内容摘要和大小，启用后检测候选变化；更新时保留当前版本并发现新候选。
- 优化：拆书核心阅读承诺贯穿原创改造、同人交接、章节计划与审校；题材专属维度按需填写，减少通用模板对作品方向的干扰。
- 优化：用户已选方向或授权直接生产时跳过重复方向比较；作者纠正按适用范围保存，写法变化使后续未稳定产物失效，并补充有限创作行为自检记录。
- 修复：审校绑定实际正文、计划、上下文与写法版本；定稿自动保护，授权覆盖前保留旧内容，上游重做后旧审校失效。
- 修复：上下文保留本章计划及上一章尾段；必需上游缺失、文件变化或前章尚未提交时停止推进，多卷章节可以明确所属卷。
- 修复：重规划否决与确认状态冲突会阻止继续生产；修复稿须重新验收，恢复记录随状态更新并保留人工备注。
- 修复：连续性迁移保留原工作区版本并备份状态，完整迁移可修复不完整的旧状态；拆书结论或证据变化会使旧交接与引用失效。
- 修复：导出默认只收录验收版本匹配的稳定正文，四位章号按数字排序，中文命令输出统一使用 UTF-8。

### 2026-10-11

- 优化：拆书透镜先比较多个核心阅读承诺，再把题材核心、心理推进、关系结构与表层兑现轴分开记录；关系型作品会保留观看位置、刺激对象和反事实检查，避免把核心观念误压成单一身体或能力递进。
- 优化：机制卡与章节参考上下文新增核心承诺、刺激对象、观看位置、心理推进和回归/依恋字段，并由校验脚本强制核对，确保拆书资源接入原创时不会丢失核心回报。

### 2026-10-10

- 新增：可从作者偏好、已有正文或授权拆书结论提炼本书写法合同；已确认的写法可作为私有资产复用，当前书保存独立快照。
- 优化：正向写法与反模板化规则从初稿起参与写作，二稿、审校和定点修文使用同一份合同与正文证据；仅提醒的问题不会自动改稿，已有正文仍受保护。
- 新增：可选的 GitHub 写法/去 AI 化 Skill 来源登记与候选审阅流程；远端版本需固定 commit 并经作者确认后才进入本地写法合同。

### 2026-10-08

- 新增：授权拆书后可从已读章末续写同人，或沿用已读设定写新故事；同人使用独立小说工作区，并在交接包就绪前暂停书级简报和章节生产。
- 新增：长篇拆书先估算原文长度与 Token 区间，再确认全文或部分阅读范围；每本书可固定拆解重点，并按批次补充角色卡。本地检索可查角色卡，不索引私有原文快照。
- 优化：模糊开书请求首轮只确认三个高影响选择；明确“没有想法”时先给五条开书种子，已有想法时提供两份可比较的简报预览。
- 优化：重整中英文项目首页，集中展示开书、题材、拆书、同人、连载和跨书复用，并提供对应的快速开始入口。

### 2026-09-30

- 新增：可选的本地阅读台，统一承载小说和拆书工作区的 Markdown，提供书架、资料分类及完整文件树，支持多个现有目录。
- 新增：中文全文搜索、页内目录、正文上下章、字号与明暗主题，以及原始资料和文件指纹查看。
- 优化：资料变化后自动更新导航、正文和搜索索引，并提示文件与状态记录的差异。阅读端仅在本机读取，不参与创作或改写权威工件。
- 优化：拆书总览新增覆盖与缺口、专项分析和复用机制工作台，校验机制证据，并支持选择目标小说与章节、准备接入请求。
- 新增：可编辑的原创改造与章节参考清单，校验来源及证据后将机制装入章节上下文；来源失效会要求重新核对，审校回看采用效果。小说总览可追踪各章参考及来源匹配情况。

### 2026-07-22 · 0.3.1

- “无想法开书”新增内部发散与商业质量门槛：围绕目标读者、代入幻想、核心杠杆、前三章兑现、长篇升级地图和追读承诺筛选后，只展示最终五条种子。
- 强钩子、人物成长、设定奇观、关系牵引和悬念追查现在作为创意功能使用，不再机械绑定题材；候选必须兼顾成熟赛道辨识度与真正改变推进方式的新变量。
- 当前检出的仓库成为明确的可编辑 Skill 源；安装镜像按 `CODEX_HOME` 或用户目录解析，功能修改只有通过完整验证后才自动进行只增不删的同步与复查。
- 根目录版本更新为 `0.3.1`。

### 2026-07-21 · 0.3.0

- 开书入口改为更适合空白起步：明确无想法时先提供五条不同风格的一句话种子；用户有想法或选中种子后，再提供两份可比较的新书简报预览，选定方向后才固化权威简报。
- 重写 README 主体介绍，明确项目已从单书章节工作流扩展为涵盖长篇连续性、跨书知识图谱和共享 IP 治理的 Codex 原生小说生产系统。
- 新增 Skill 镜像新鲜度检查：首次使用以及 Skill 表面改动后，先比对权威源与已安装镜像，明确报告缺失、差异和镜像额外文件，避免在过期副本上继续生产。
- 验证通过后可用只增不删的同步命令更新安装镜像并复查；权威源缺失时必须显式报告，不会静默替换来源。
- 新增根目录 `VERSION`，当前发布版本为 `0.3.0`。

### 2026-07-20

- 新增跨书知识图谱开发看板，集中说明当前 Codex 原生方向、已交付的三期能力、后续候选项和明确不纳入当前路线的外部服务边界。
- 跨书资产库现默认一库一共享 IP 宇宙：已发布 `universe/event` 资产可用稳定序号、参与资产、影响和先后关系派生正史编年史。
- 新增 `timeline`、`canon-check`、`impact` 与 `delegate-universe` 命令；影响审查只报告显式工作区的同步链接、章节选择和时间线邻域，不会改写正文、快照或正史。
- 新增可撤销的宇宙级 Codex 正史委托；作者批准、按资产委托或有效宇宙委托均可授权 `universe` 发布，`reusable` 仍保持按资产治理。
- 正史事件发布会校验已发布同宇宙端点、来源证据、顺序矛盾和循环关系；SQLite 继续只是可重建索引。
- 跨书资产图谱现可进入章节生产：Codex 先提出可编辑选择清单，再将锁定快照、用途、约束和权威回读路径装入有限章节上下文。
- 选中的同步资产发生冲突时，上下文、正文和审校会安全停止；共享库有更新时默认固定本书版本并提示处理，不自动覆盖内容。
- 已验收且已提交连续性的章节可产生带正文指纹和证据的待发布资产候选；候选验证后仍遵守作者批准或可撤销 Codex 委托。
- 新增本机私有、默认 Git 忽略的跨书资产库：可复用机制资产与共享 IP 正史可分别以 `fork` 或受保护的 `sync` 导入 schema v3 小说。
- 新增 `asset_graph.py`，提供资产发布、作者批准/按资产委托 Codex、撤销委托、同步检查、显式冲突处理、JSONL/SQLite 派生图和有限上下文候选查询。
- 图谱只接纳已验收连续性及已批准/委托的定稿资产；同步与冲突处理不会静默覆盖受保护正文或其他权威资料。
- 明确 Codex 原生边界：Codex 是唯一创作与判断引擎，Skill 是过程合同，脚本只做确定性处理；不引入 Provider SDK、Web API、数据库权威、队列或自研 Agent Runtime。
- 新增 Codex 原生 `novelctl.py` 工作区控制器，统一提供初始化、状态、唯一下一步、校验、显式迁移、步骤转换、阻断恢复、上下文、检查点、用量与稳定正文导出。
- 新工作区采用 `novel-state.yaml` schema v3；v1/v2 保持只读兼容，迁移必须显式执行并先生成备份，失败不会伪造 `ready`。
- 新增里程碑审批和章节范围授权投影；章节始终单 Agent 串行生产，每章稳定并提交连续性后才规划下一章。
- 开书三项选择成为 schema v3 的强制语义门槛；未确认频道、发布形态和主要阅读回报时，控制器不会启动书级简报。
- 新增用户资产指纹保护：已验收正文或规划被作者修改后保留原文，仅将未写下游标记为 `stale`。
- 新增 Codex-only 架构合同、生成步骤目录、质量债与恢复规则；不接入模型 Provider、Web UI、数据库权威或自研 Agent Runtime。
- 新增权威仓库与安装镜像的哈希校验/同步工具；同步不会删除镜像中的额外文件。
- `novelctl export` 仅导出正文和连续性状态均为 `ready` 的稳定章节，不再仅凭文件存在判断。
- 新增逐生成步骤 Token 用量合同；规划、正文、润色、审查、修复、连续性回灌、拆书和趋势报告等模型调用可分别记账。
- 新增 `token_usage.py`，支持追加记录、账本校验，以及按步骤和模型生成汇总视图。
- 精确 usage、兼容 tokenizer 估算和运行时不可获取事件严格分开；缓存输入与推理 Token 作为明细，不重复计入总数。
- 失败和重试保留独立事件；用量账本不得保存提示词正文、密钥或创作上下文，也不得进入章节上下文包。
- `novel-state.yaml` 只保存简短累计投影；追加式 JSONL 账本为用量事实源，汇总文件可随时重建。

### 2026-07-17

- 新增参考小说拆解与用户稿件诊断路线，可处理已授权本地文本、可访问线上来源和现有小说工作区。
- 拆书采用“范围与指纹 → 分段笔记 → 总览 → 八类专项小节 → 证据与反例 → 机制卡”的可恢复流程，并明确区分全量覆盖与抽样分析。
- 关键判断区分事实、推断和假设，记录置信度、来源锚点、反例与适用阶段，降低长篇抽样外推和无依据结论风险。
- 新增阶段变化、读者体验、因果机制和原创改造检查，帮助作者学习有效原理，同时避免大段复述或贴近原作仿写。
- 新增私有 `analyses/` 工作区约定，原文和拆书产物默认不进入公开仓库。
- 长篇拆书新增轻量 BookGraph 和 SQLite 中文全文检索，可按人物、章节、维度、关系邻域和因果路径提取必要上下文，不再为每次专项分析重复读取全部 notes。
- 向量检索作为可选 sidecar 接入：未配置 embedding 时保持零第三方依赖并自动使用图、元数据与全文检索；配置兼容向量后可做余弦召回和排名融合。
- 新增独立的热门题材趋势路线，按需读取公开官方榜单元数据，并在网页不可访问时接受用户提供的截图、表格或文本。
- 新增私有 `trends/` 工作区、榜单快照合同、趋势报告和机会卡；原始榜单与未选机会卡不会进入小说创作上下文。
- 新增零第三方依赖的 `trend_snapshot.py`，支持校验快照、统计表层信号以及比较同平台同榜单的可比日期；脚本不内置爬虫、题材词典或趋势判断。
- 新增渐进式内容设定确认：在开书、故事发动机、世界角色、卷规划和首章前，每轮只引导确认 2–3 个高影响选择，并提供推荐与影响说明。
- 新增项目级选择记忆：已确认、已授权 AI 决定和不适用的设置不会被重复询问；未确认推荐只可预览，不能固化为权威资产或驱动正式下游规划。
- 连续性存储升级为 YAML 权威数据、自动生成的 Markdown 台账视图与可重建 SQLite 索引；可按章节和角色组装有限上下文，并通过检查点支持长期恢复。
- 新增旧工作区的安全迁移、YAML/索引一致性校验与直读降级：索引缺失或过期不会改变事实，也不会阻塞续写恢复。
- 章节生产明确保持单章串行回灌，暂停多子代理预热，避免未验收候选进入长期连续性。
